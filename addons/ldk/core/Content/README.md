# Conteúdo do LDK

O `ContentPack` descreve um pacote. A `ContentLibrary` descobre os arquivos PCK, verifica seus caminhos, lê os manifestos, ordena dependências e publica o `ContentDB`. O banco indexa as definições por categoria e prepara o catálogo compacto do terreno no primeiro uso. Os registros são fechados antes de abrir o menu.

O editor usa `ContentLibrary.discover_folders()` para descobrir Resources e manifestos nas pastas configuradas, aplicando as exclusões antes de carregar. O resultado mantém os caminhos de origem e associa os namespaces válidos às pastas dos manifestos para montar a árvore de navegação. `ContentLibrary.from_manifests()` registra os manifestos descobertos com a mesma validação de pacotes e referências do jogo. O banco e os Resources de conteúdo podem ser lidos no editor Godot por scripts `@tool`. Ao rejeitar geometria de bloco, o banco informa o ID e o motivo retornado pela definição `VoxelBlock`.

## Criação de um pacote

1. Escolha um namespace, por exemplo `technology`. Crie `mods/technology/content.tres` como um `ContentPack`. Use `content_namespace = "technology"`, `version = "1.0.0"` e `api_version = 1`. Declare `dependencies = {"core": "1.0.0"}` se o pacote usar conteúdo nativo. Uma dependência exige a mesma versão principal e ao menos a versão indicada.
2. Salve cada bloco, entidade, item, bioma e receita em seu próprio Resource. Associe-os aos campos do manifesto como no pacote nativo em `assets/core/content.tres`. Use `namespace:nome` nos IDs e nas referências, com letras minúsculas, números e sublinhados. Cada parte começa com uma letra e cada ID é único em sua categoria. O namespace `core` é reservado. A leitura também aceita o separador legado `@`.
3. Para reutilizar recursos, referencie os IDs registrados pelo pacote de origem e declare a dependência. `biome_overrides` aceita uma definição completa de bioma no ID original. Entre substituições válidas, vence a primeira em ordem de registro. Para usar um bioma novo, inclua-o no preset de mundo ou deixe o preset sem lista explícita para usar todos os biomas registrados.
4. Empacote os arquivos com `PCKPacker`, usando destinos sob `res://mods/technology/`, incluindo o manifesto e suas dependências locais. Use um PCK independente sem criptografia. Para imagens importadas, inclua o remapeamento e respectivos arquivos de importação sob a raiz do pacote, ou empacote texturas como Resources autossuficientes, por exemplo `ImageTexture` em `.res`. Inclua também os caminhos referenciados só por string em `deferred_textures` e `scene_path`. Um PCK com toda a raiz de um projeto é rejeitado se contiver arquivos fora do namespace. [Godot — Exporting PCKs and Mods](https://docs.godotengine.org/en/stable/tutorials/export/exporting_pcks.html)
5. Coloque o arquivo em `user://mods/technology.pck` e reinicie o jogo. A biblioteca aceita apenas arquivos próprios do namespace e monta com substituição de arquivos desativada. Use pacotes de fontes confiáveis, pois scripts de um Resource podem executar código no processo do jogo.

O pacote nativo registra primeiro. Quando vários pacotes estão prontos, a maior `priority` passa primeiro e o namespace resolve o empate. Uma dependência sempre registra antes do pacote que a exige. Se dois pacotes se declaram incompatíveis por `conflicts`, o primeiro aceito tem preferência. Pacotes com versões incompatíveis, dependências ausentes, ciclos ou definições inválidas aparecem nos avisos. O banco conserva as definições válidas com referências ausentes para permitir fallback.

## Consultas e componentes

- Use o registro da categoria, como `database.blocks.find(&"core:stone")`, para consultar um Resource compartilhado. A View resolve texturas por ID e usa um padrão quadriculado quando necessário. O terreno tem 255 camadas de textura disponíveis além do fallback.
- Blocos e entidades têm componentes próprios como geometria, visual, colisão, resistência e drops. Para um componente adicional de mod, registre o Resource em `ContentPack.components` e associe seu ID ao campo `component_ids` da definição. `database.component_for(definition, id)` consulta o vínculo indexado no carregamento. Os sistemas que conhecem o componente são responsáveis por seu comportamento e estado.
- `ContentDrops` mantém quantidades fixas em `items`. Para sortear uma quantidade, use `items` como mínimo e informe o máximo inclusivo em `maximum_by_item`. `ContentSceneVisual.batch_texture` e `batch_size` descrevem os sprites agrupáveis de entidades sem colisão.
- O campo `InventoryItem.entity_id` referencia uma entidade decorativa com sprite agrupável. O banco valida a referência e avisa se o item também tiver `block_id`.
- O campo `ContentScene.wildlife` define uma entidade de fauna temporária. O banco valida a forma de colisão e as referências de biomas e blocos do perfil. A população usa a cena visual e a forma física como componentes independentes.
- O seletor recebe descritores `ContentComponentType` de `database.component_types(alvo)`. Os tipos nativos são registrados por `builtin_component_types.gd` com IDs `ldk:*`. Para oferecer um tipo de mod, coloque o descritor em `ContentPack.components` com um ID do pacote. Preencha nome, categoria, descrição, finalidade, alvos e um Resource protótipo com os valores padrão. O ícone é opcional. Para o alvo `block`, use um protótipo compatível com uma porta do grafo, como um preset `VoxelVisual` com script `@tool`. O grafo salva o componente criado nos campos da definição.
- O chunk continua armazenando IDs compactos em memória. Ao exportar edições de mundo, use os IDs estáveis do catálogo. Referências a blocos de mods ausentes são preservadas para uma futura restauração.

A descoberta, ordenação e validação de pacotes seguem a separação entre carregamento e registro usada por Factorio. A montagem de arquivos e a resolução de Resources usam o Godot. ## Atalhos de pacotes

Adicione Resources `GameActionDefinition` a `ContentPack.input_actions` para registrar atalhos no mesmo processo do restante do conteúdo. Use um ID do pacote como `technology:open_panel`, preencha a categoria, o rótulo e os eventos padrão. Ações com o mesmo `category` aparecem juntas no painel de controles. Consulte o mesmo ID no `InputMap` para usar a ação no jogo.
